システム要件定義書・基本設計書

1. システム概要

本システムは、日々のジャーナリング（日記記入）を中心に、To-Do管理、カレンダー参照、タイマーなどの補助機能を搭載したローカルファーストなパーソナルログアプリケーションです。ローカルLLM（Llama等）を利用した日記データの要約機能を提供し、個人の振返りを支援します。

2. 機能要件

2.1 日記・ジャーナル機能（メイン画面）

日別ジャーナル表示: 1日につき1画面（1ページ）で日記を入力・表示する。

「今日あったこと」記入欄: テキスト形式で自由な記述が可能なエディタ領域を提供する。

日時データ自動紐付け: 選択中の日付に応じた日記データを表示・更新する。

2.2 カレンダー・現在時刻取得ツール

現在時刻表示: リアルタイムな現在時刻を表示する。

カレンダー表示: 月表示形式のカレンダーを表示し、過去・未来の日付を選択して該当日のジャーナル画面へ遷移できるようにする。

2.3 To-Do List

タスク管理: タスクの追加・編集・削除・完了チェックを行う。

画面遷移: メイン画面からTo-Do専用画面への遷移が可能。

2.4 タイマー機能

カウントダウン/ストップウォッチ: 作業や集中時間を計測するタイマー機能。

画面遷移: メイン画面からタイマー専用画面への遷移が可能。

2.5 ローカルLLMによる要約機能

過去ログの要約: ローカルで動作するLLM（Llama等）と連携し、指定期間（例: ここ1ヶ月間など）の日記テキストデータを分析・要約する。

要約結果の表示: 生成された要約結果を表示・保存する機能。

3. 非機能要件・データ構造設計

3.1 データ保存および永続化

保存先: ブラウザのローカルストレージ（localStorage）。

データ形式: 外部連携やバックアップを考慮し、テキスト（JSON / Plain Text）形式で保存。

データ構造案:

{
  "journals": {
    "YYYY-MM-DD": {
      "content": "今日あったことの内容...",
      "updatedAt": "2026-10-26T14:12:00Z"
    }
  },
  "todos": [
    {
      "id": "uuid",
      "text": "タスク内容",
      "completed": false,
      "createdAt": "2026-10-26T14:12:00Z"
    }
  ]
}



3.2 アプリケーション構成・画面遷移（画面設計）

デフォルト表示: アプリケーション起動時は常に「本日のジャーナル（日記）画面」を表示する。

画面遷移方式: 各機能（To-Do List、タイマー、カレンダービュー、LLM要約）へは画面遷移（またはビュー切り替え）で移動する構成とする。

[ジャーナル画面 (デフォルト)] 
   ├──> [To-Do List 画面]
   ├──> [タイマー画面]
   ├──> [カレンダー参照画面]
   └──> [LLM要約画面]



4. 今後の検討事項

ローカルLLM連携方式: WebLLMなどのブラウザ実行型、あるいはOllamaなどのローカルAPI連携（REST/WebSocket）のどちらを採用するか。

データのバックアップ/復元: ローカルストレージ消去対策としてのJSONファイルの書き出し（エクスポート）・読み込み（インポート）機能の検討。
